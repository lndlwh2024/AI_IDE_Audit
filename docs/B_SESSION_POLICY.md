# B 会话归属、复用与历史策略

更新：2026-09-09，按用户最新确认执行。B 使用 Codex 原生大模型任务，必须位于 A 的同一项目。用户接受 B 的宿主读写权限；审计任务本身不要求修改代码。

| 场景 | 行为 | 历史 |
|:---|:---|:---|
| 首次提交 | 核验准确根目录和真实 projectId，创建 B1，A 打开该任务 | 新聊天 |
| 同一次运行中多次提交 | 串行使用同一个 thread_id；桌面持有时通过原生接口续发 | 原聊天保留，新轮次只按本轮需求裁决 |
| 再次启动 Codex | 读取持久绑定，优先恢复原 B；活动写入者走原生桥接 | 原 B 仍存在时继承其历史 |
| B 被归档 | 不取消归档；下一次创建同项目 B，序号加一 | 旧历史留在归档任务，新 B 不回放旧消息 |
| B 明确不存在 | 创建同项目新 B，序号加一，记录前任 ID | 不恢复已经删除的聊天；本地报告另行保留 |
| 权限、网络、未加载等临时错误 | 保留原 ID 和队列，报告问题 | 不据此创建重复 B |
| 上轮尚在运行 | 等待并回收原轮次结果 | 不抢占或重复派发 |
| 领取后发送结果不明 | 先核对/回收原 B，保留待处理状态 | 不用超时推断消息未发送 |

活动写入者桥接已经实机通过，因此无需把“每次退出都新建 B”作为默认策略。用户提出的删除 B 方案是解决不了冲突时的备选；当前不自动弹出删除流程，永久删除仍必须经用户明确确认。

B 内可直接追问。CLI ask 用于独立 app-server 能恢复该 B 的情形；若桌面已持有 B，使用原生 B 对话继续提问。原生聊天历史由 Codex 保存，本地 verdicts/results 是审计产物，两者不是同一份历史；新 B 不伪装展示旧聊天。

实机已通过同项目、多轮复用与归档后 B2；没有关闭整个桌面应用或永久删除任务做实验。详细证据与限制见 [宿主兼容性](HOST_COMPATIBILITY.md)。
