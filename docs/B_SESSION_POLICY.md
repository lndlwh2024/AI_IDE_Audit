# B 会话归属、重启与历史策略

更新：2026-09-09。用户明确要求：在 NEWS 项目 A 中完成 commit 后，B 必须出现在同一个 NEWS 项目下。该要求为必要验收条件，不是可选的界面优化。

## 1. 当前发现与尚未完成项

本地 app-server 的 `thread/start` 支持 cwd，但当前生成的协议没有桌面 projectId 参数。实测在已注册项目 `AI_IDE_Audit` 的准确目录创建 B，返回的 cwd 正确，桌面任务列表仍返回 `projectId: null`。因此，同工作目录和同桌面项目不是一回事。

测试会话：`01a08489-2fe8-7d01-80d9-6c7257e79886`，仅包含测试消息和 READY 回复。已注册的 AI_IDE_Audit 项目 ID 是 `2a68123d-d201-4d63-b5a8-18e68bc16dfa`，两者归属没有匹配。没有读取或修改 NEWS 项目源码。

必须增加可正式调用的桌面适配层，按 A 的真实项目 ID 创建/关联并打开 B，验证桌面返回同一项目 ID；没有完成绑定时不能宣称“同项目 B 已完成”。当前会话中的 Codex 桌面工具有带 projectId 的任务创建能力，但还未将其转换为安装后可由插件自动调用、且保留只读隔离的接口。禁止通过修改 Codex 内部数据库实现伪绑定。

## 2. 已实现与已验证策略

| 场景 | 当前处理 | 历史情况与证据 |
|:---|:---|:---|
| 首次审计 | 在 A 对应目录新建持久 B，记录 thread_id | 第一次轮次后保存；仅创建空会话不足以验证持久化 |
| 原 B 仍存在，后续新提交 | 用保存的 ID 执行 thread/resume | 继续原聊天，每次裁决只以本轮固定需求和提交为授权 |
| 关闭客户端进程后重新连接 | 恢复原 ID，保留历史轮次 | 已实测 READY 的原轮次 ID 和原回复保留；没有关闭当前用户的整个 Codex 桌面应用 |
| 原 B 被归档 | 下次提交新建 B，记录替代关系；不取消旧 B 归档 | 新 B 不回放旧聊天；旧聊天由 Codex 保存在归档任务中。精确错误分支已加入自动化测试，同桌面项目绑定仍待完成 |
| 服务端明确返回 no rollout found | 新建空白 B，更新 ID 并记录旧 ID 的关联 | 本轮新增；以真实协议错误格式及自动化测试验证。不会把原聊天重新注入新 B |
| 网络、权限、thread not loaded 等错误 | 保留原 ID 并报错 | 不将暂时失败当成删除，避免重复创建会话 |
| 返回的 B 目录与 A 不同 | 停止派发 | 本轮新增目录校验；仍不能代替桌面项目 ID 校验 |
| 退出时上一审计仍在进行 | 原任务可能需要 recover，后续提交可能等待 | 尚未完成整个桌面强退/长任务自动恢复矩阵，不能声称始终无感恢复 |

`no rollout found` 说明当前服务无法找到对应会话，不单独证明用户点击过永久删除。未实际删除任何用户会话。

## 3. 删除聊天与删除项目报告不同

Codex 聊天历史由 Codex 保存；插件的 `.ide_audit/results`、`verdicts`、`questions` 是另外保存的审计产物。

永久删除 B 后，不承诺恢复完整原始聊天。重建的 B 默认是新聊天，不自动展示过去的消息。项目内审计报告和通过插件发起的问答记录如未被删除仍可查询，但不是完整聊天的替代物，不能伪装成原会话历史。若未来提供历史报告导入，应明确标记为旧报告材料，并由用户主动请求。

## 4. 后续验收优先级

最高优先级：同一桌面项目 ID 下创建及自动打开 B；正常应用重启、新提交继续原 B；永久删除 B 后新建空白 B；归档后新建 B，网络故障不得误触发重建。其次完善运行中退出、忙碌队列和大历史记录的恢复。

参考：[官方 app-server 会话恢复文档](https://learn.chatgpt.com/docs/app-server)、[官方项目与聊天说明](https://learn.chatgpt.com/docs/projects)。本文件中的项目归属结论来自当前桌面实测，不能从 cwd 参数推导出绑定成功。
