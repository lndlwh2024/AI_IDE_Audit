# IDE_Audit 开发执行计划

更新：2026-09-10；交付目标 0.4.0。此前分阶段用于实施顺序，不缩减用户确认的整体开发范围。

## 已落实的需求

1. 一个插件完整承接原 Skill 的逻辑工作流：事件、诊断纠错、会话游标、冲突与租约、图谱、交接和派生文档。旧项目业务迁移独立交付，不进入插件。
2. A 每次接入先建图或刷新图谱，成功后才能编辑；后续由 A 动态更新。增量缓存避免重复读取和解析未变 Python 文件，新增依赖仍重新解析关联目标，保留人工语义。
3. 同项目原生 B 使用现有 Codex 大模型，持久绑定真实项目和任务 ID。活动写入者通过桌面原生派发解决；同次运行复用，归档或确实丢失才新建并递增编号。允许宿主读写权限，审计工作流不修改代码。
4. 固定提交事实链、完整原始需求、逐文件强相关裁决、队列恢复、可安装插件及外部切换工具统一交付。

## 开发项与验收

| 开发项 | 完成内容 | 验证 |
|:---|:---|:---|
| 审计事实链 | 固定 SHA/第一父提交、真实 patch、批次与输入哈希、只读 core | 提交/重审/根提交/范围与缺证回归 |
| 协同融合 | 12 类事件、诊断更正、独立游标、完整视图 | 模型、并发、游标回退与交接回归 |
| 增量图谱 | 文件缓存、AST 缓存、依赖重解析、人工语义保留 | 增量与全量一致、增删文件、零重复读取/解析 |
| 租约与事务 | 目录范围冲突、所有者续期、跨账本/图谱/游标 journal | 竞争、过期、半写恢复、幂等操作编号 |
| 同项目原生 B | 实验项目协议、持久绑定、序号和归档替代 | 真实同项目、多轮模型裁决、真实 B2 |
| 桌面冲突与队列 | 原生交接、B 新轮次结果核验、等待阻塞后续提交 | 真实桌面持有者、忙碌/去重/错误标识与恢复分支 |
| 外部 NEWS 工具 | 只读预检、转换、停用项目旧 Skill、安装及等待 A 验收 | 单向切换回归、140 事件/612 节点只读预检；真实 NEWS 未切换 |
| 发布 | 完整插件 ZIP、wheel、独立切换 ZIP、校验和 | 清单/Skill 校验、隔离 wheel 加载；发布证据见 HANDOVER |

本地完整回归为 117 项通过。交付检查顺序为文档校正、最终构建和安装检查、提交推送、GitHub CI 与发布附件；只有实际成功的步骤才记为发布完成。

## 交付后的验证边界

完整桌面强退重启、多种 Codex 版本和超大输入压力测试未实测。它们列为兼容性扩展验证，不再称为本轮尚未编写的功能。首次真实 NEWS 切换需在该项目停止旧写入者后运行外部工具；本次交付工具，不擅自执行真实业务迁移。领取与原生发送之间中断时明确进入人工核对，不能宣称跨系统恰好一次自动恢复。


## 已确认新增项（0.4.0）

| 项目 | 实现与验证 |
| --- | --- |
| 每项目授权 | 未选择/拒绝/待 A/开启/暂停状态；缺失或异地复制默认关闭；真实项目核验 |
| 启动询问 | 标准 SessionStart Hook、Windows 含空格路径命令测试；用户信任后运行，未信任可手动开启 |
| A/B 暂停与恢复 | B 只提出恢复，A 更新当前图谱/同步；失败保持等待；旧需求归档、队列明确恢复 |
| B 用量 | 真实来源、分项、轮次去重、计数回退/缺失未知；原生 B 日志读取实测 |
| 外部 NEWS 切换 | 单向保留资产，停用旧入口，真实 B 完成前不宣布迁移完成 |

待用户环境验收：信任本插件 Hook 后实际进入项目的询问；完整桌面退出重启；NEWS 的 A 接入及下一次实际授权开发提交。这些动作不能由脚本模拟替代。公共市场提交暂不执行。
