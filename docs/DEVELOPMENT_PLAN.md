# IDE_Audit 开发执行计划

更新：2026-09-10；交付目标 0.4.0。此前分阶段用于实施顺序，不缩减用户确认的整体开发范围。

## 已落实的需求

1. 一个插件完整承接原 Skill 的逻辑工作流：事件、诊断纠错、会话游标、冲突与租约、图谱、交接和派生文档。旧项目业务迁移独立交付，不进入插件。
2. A 每次接入先建图或刷新图谱，成功后才能编辑；后续由 A 动态更新。增量缓存避免重复读取和解析未变 Python 文件，新增依赖仍重新解析关联目标，保留人工语义。
3. 同项目原生 B 使用现有 Codex 大模型，持久绑定真实项目和任务 ID。活动写入者通过桌面原生派发解决；同次运行复用，归档或确实丢失才新建并递增编号。允许宿主读写权限，审计工作流不修改代码。
4. 固定提交事实链、完整原始需求、逐文件强相关裁决、队列恢复、可安装插件及外部切换工具统一交付。

## 交付后的验证边界

完整桌面强退重启、多种 Codex 版本和超大输入压力测试未实测。它们列为兼容性扩展验证，不再称为本轮尚未编写的功能。首次真实 NEWS 切换需在该项目停止旧写入者后运行外部工具；本次交付工具，不擅自执行真实业务迁移。领取与原生发送之间中断时明确进入人工核对，不能宣称跨系统恰好一次自动恢复。

## 2026-09-12：0.4.3 环节用量日志

用户澄清：无实际代码/文档改动不追加修改账本；实际改动尚未 commit 仍在任务完成/交接时记录增量。图谱仅语义变化时更新，有 commit 才送 B。

已实现：MCP 全部工具自动记录操作名、角色、阶段标识、耗时、输入输出字符/字节数及失败类型；phase_finished 保存宿主区间五项计数与窗口累计；commit_enqueued 与 b_audit_finished 关联提交和 B 任务。日志保存在 .ide_audit/operation-usage/，通过 get_operation_usage_log 或 operation-usage 分页读取。模型正文不写入日志；未授权不因工具探测生成日志；记录失败警告而不重试已成功业务动作。

边界：工具大小不等于完整模型输入。宿主统计可能延迟/重置，无法精确独占归因，未知不填零。不要把重叠区间或 B 同一 turn 重复观测累加。阶段关联只适用当前服务顺序工作流，不支持并行阶段。直接 CLI/Python 维护不经 MCP 时无逐工具日志；入队及 B 完成仍记录。硬退出尚未返回的工具可能没有完成日志。日志长期保留，分页返回，不向模型全量加载。

估算口径（规划参考，不是实测或计费承诺）：空账本检查/锁摘要约数百字符；少量新增事件限制每页 12000 字符；单模块无架构变化只传必要事件与短结果，不按全库大小增长；B 当前包上限 64000 字符。中英文与 JSON 的 tokenizer 比例不同，不把字符硬换算为实际 token。若假设短英文/JSON 摘要，空检查额外载荷约 100–500 token，少量事件对齐约 500–3000，单模块简短记账约 300–1500，小 diff 新 B 约 3000–15000；中文、长 diff、规则和上下文可能超出。以上排除业务编码和既有 A 历史。NEWS 原 A 单轮约 13 万输入，减少载荷不能消除历史上下文成本，应尽量批量本地步骤、避免调试往返；新 A 需保留必要工作交接。

NEWS 后续验证使用既有 db8aec5ffe221585a47224a4c76e54ce327141df：提交已成功，失败的是后面的送审。查状态后恢复其通知，不创建新提交、不篡改封存证据。真实 NEWS B 尚待用户执行提示词验收，不能宣称已完成。


## 2026-09-13：0.4.4 人读报告与用量归属

问题：0.4.3 的 B 直连 outputSchema 与桥接“仅输出 JSON”要求，使最终回复成为裸机器对象；commentary 用量在最终界面缺失。NEWS db8aec5f 的真实 B 已完成并判不合理，原因是行级申报遗漏，而不是文件完全没记账：v0141 存在，文档实际 +1 行，lines=null。历史“真实 B 尚未启动”不再是当前状态。

实现：移除强制裸 JSON 的输出约束，保留严格 schema、提交/逐文件校验与桥接 request_id 防串单；解析兼容旧 JSON 和新正文末尾唯一 JSON 附录。最终报告固定四段：插件事实、B 需求/实现对比（逐文件、架构、账本）、最终结论/整改、各环节预测与本次/累计用量。format_audit_report 只排版，不代替 B；get_final_audit_report 只使用已保存 B 裁决。B 回收及用量保存后生成 .ide_audit/reports/<SHA>.md；排版失败不能诱发重复送审。折叠附录的显示方式取决于宿主。

用量：A 提交准备显式携带 measurement_ids，并验证开发基线；ID 随提交证据封存。提交后快照可传 audit_id。报告只读取绑定阶段，多次观测分行，不将其他阶段或其他提交用量填表。新增 estimate_audit_usage；B 按实际证据字符数给宽区间载荷预测，A 短摘要提供规划参考。预测不包括宿主历史、系统/工具输入和输出，不能当作总成本预算或额度承诺。缺失历史计数不补造；老提交可重新排版，不需再次调用 B。

业务规则：无修改不记账；零字节新增文件记文件事件，没有新增行时不要求虚构行号；新增文字必须申报相应行范围。图谱物理节点变化与业务架构越权分开说明。保留原始封存记录，不回填历史以制造通过。


## 2026-09-13：0.4.5 B 展示与阶段自动关联修复

完整报告在 B 最终回复及 B 文件面板展示；A 仅显示自己的阶段用量、派发状态与 B 入口。回收后的报告由 A 使用 open_in_codex 定位到已核对的同项目 B 面板，不额外调用 B 模型重印报告。宿主能力缺失时明确报告阻塞，不改在 A 输出全文。

首次阶段记录识别当前真实 A，MCP 提交准备自动收集该任务同基线的阶段记录并封存，兼容显式清单。提交后阶段继续传 audit_id。累计独立保存有效宿主观测，B 排版时刷新所属 A 的累计并列出时间；阶段缺失不再连带隐藏已有累计。阶段区分无记录、未结束、待结算、计数缺失/重置；加锁等本地操作关联父测量区间时标注共享，不假报独占成本。旧提交缺少 A 任务关联时不猜测任务、不回填历史封存证据。

边界：没有有效宿主观测就无法承诺必有数值；同一模型请求内本地步骤无法准确分摊 token。日志与提交绑定并不能将缓存、历史上下文或等待后新增请求变成独占步骤成本。真实 NEWS 新提交端到端验证交由用户执行独立提示词；本轮更新不创建 NEWS 提交、不重跑 B。
