# Codex Windows 宿主兼容性

更新：2026-09-09；验证 CLI 0.153.4。B 始终是 Codex 原生任务，由现有账户的大模型审计，没有替代网页、独立模型服务或内部数据库修改。

## 项目归属

使用实验协议初始化、project/list 按准确项目根目录唯一匹配，再以 thread/start.projectId 创建 B。旧 B 缺少绑定时，在核验目录后通过 thread/metadata/update 补齐；跨项目或目录不符直接停止。

实际项目后端 ID 为 `01a07f99-a552-7970-b3b7-42d3c8c755c9`，桌面 ID 为 `2a68123d-d201-4d63-b5a8-18e68bc16dfa`。两套 ID 不可混用。测试 B `01a085b8-8a3e-74f3-a09b-00d845772d64` 在桌面打开后归入 A 的同一项目。

## 活动写入者解决方案

独立 app-server 恢复桌面已持有的 B，确实返回 `already has an active writer`。当前 Windows 的 daemon 不能提供共享连接，不能假称消除了宿主锁。

插件改为协作派发：后台遇到该精确错误，封存带随机请求标识的完整审计消息；统一 A Skill 领取后使用 Codex 桌面原生 send_message_to_thread 发给既有 B。随后插件通过 thread/read 读取 B 的真实新轮次，核验请求标识、完整提交 SHA、逐文件覆盖和裁决一致性，再落盘。A 不提供或代写裁决。队列在待桌面派发时暂停后续提交，避免串单；重入时先回收原请求，不能重复发送。

领取与宿主发送不能组成跨进程原子事务。若 A 在两者之间中断，状态明确保留为 desktop_sending，需要核对原 B；不能仅凭超时自动重发。后台 Hook 单独运行时可保存队列；桌面接管路径需要 A 的统一 Skill 执行原生交接。

## 权限与验证范围

用户已明确接受原生 B 读写权限。后台独立连接仍请求只读沙箱；桌面继续对话可使用宿主权限，不能承诺系统级强制只读。B 守则要求审计时不改代码；插件 core 与审计 MCP 保持只读，A 维护协同元数据。

没有关闭用户整个 Codex 应用做强退重启实验，也没有永久删除用户聊天。已验证服务进程重连、真实原生同 B 多轮、真实归档替代；跨整机重启、其他 Codex 版本及超大事实包属于兼容性验证边界，不能从本次结果外推。实验协议版本变化需重新验收。
